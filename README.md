# Мониторинг цен на авто

Telegram-бот следит за каталогами автомобилей с пробегом и публикует в группу с темами новые предложения и снижения цен.

## Как это работает

```
каталоги сайтов ──► процессор источника ──► PostgreSQL ──► уведомления ──► группа Telegram
                    (разбор страниц)        (машины,        (шаблоны,       ├─ тема «новые»
                                             история цен)    фото)          └─ тема «снижение цен»
                                                                ▲
                                   сбой источника ──────────────┴──► личный чат админа
```

Бот работает в двух режимах, по расписанию в часовом поясе Москвы:

| Режим | Что делает | Когда |
|---|---|---|
| **Поиск новых** | Смотрит первые страницы каталогов (сортировка от новых к старым) и отправляет машины, которых ещё нет в базе | раз в минуту, `NEW_CARS_HOURS` в `WORK_DAYS` |
| **Обновление цен** | Обходит каталоги целиком, обновляет цены, пишет историю и отправляет снижения | `UPDATE_CARS_HOURS` в `WORK_DAYS` |

При старте контейнера оба режима запускаются один раз в фоне. Бот начинает отвечать сразу, не дожидаясь окончания обхода. Сбор идёт в отдельном потоке, поэтому команды бота не блокируются даже во время полного обхода (~15 минут).

### Сообщения в группе

**Новые машины** приходят по одной, с фото и без звука:

```
🆕 Новое предложение
🚗 VOYAH Free · #легковые #VOYAH
📍 #Москва · 2023 · 45 806 км
💰 3 134 700 ₽ · 44 728 ₽/мес
🔗 Подробнее · <источник>
```

**Снижения цен** тоже приходят по одной, с фото, но со звуком. Самые большие скидки идут первыми. Типы техники из `SILENT_CAR_TYPES` (по умолчанию легковые) уходят отдельной пачкой без звука — пост в теме есть, но телефон он не будит:

```
📉 −90 000 ₽ (−9,6%)
🚗 VOYAH Free · #легковые #VOYAH
📍 #Москва · 2023 · 45 806 км
💰 940 000 ₽ → 850 000 ₽
📊 Снижается 4-й раз · −15,0% от первой цены 1 000 000 ₽
🔗 Подробнее · <источник>
```

- **Хэштеги** (тип, марка, город) кликабельны: нажатие на `#Москва` показывает все сообщения с этим тегом.
- **Если за запуск больше 20 машин** (первый запуск, распродажа), первые 20 идут отдельно, остальные — сводкой «Ещё N…», разбитой на части «Часть 2 из 5».
- **Если фото не скачалось** или Telegram его не принял, сообщение уходит текстом.

У каждого источника свои темы — «Новые» и «Снижение цен». В сообщении о снижении есть ссылка «📌 Первый пост» на пост о появлении машины: так историю машины видно, хотя новые и снижения лежат в разных темах.

**Итоги дня** уходят в общий чат группы в `DAILY_SUMMARY_HOUR` по будням: сколько машин появилось по каждому источнику и типу, сколько было снижений и пять лучших снижений дня.

### Когда снижение попадает в группу

Снижение считается не от предыдущей цены, а от **отправной точки** — цены, которую читатели видели последней: стартовой или из прошлого уведомления. Уведомление уходит, если цена упала от неё не меньше чем на `NOTIFY_PRICE_DROP_PERCENT` процентов. Так несколько мелких снижений подряд складываются в одно уведомление, а не теряются под порогом:

```
1 000 000 → 970 000   −3%                        без уведомления
  970 000 → 940 000   −6% от отправной 1 000 000  📉 уведомление, новая отправная — 940 000
```

Рост цены записывается в историю, но уведомлений не даёт.

### Алерты админу

В личный чат `ADMIN_CHAT_ID` приходит одно сообщение, когда источник сломался, и одно — когда снова заработал. Пока источник лежит, повторных алертов нет.

Сбоем считается:
- исключение при сборе;
- 0 собранных машин;
- запросы, которые не прошли даже после повторов;
- ошибка записи в базу;
- для обновления цен ещё — собрано меньше половины машин от прошлого запуска.

Поиск новых сообщает о сбое после 3 неудач подряд, обновление цен — сразу.

## Структура проекта

```
src/
  main.py                   точка входа
  schedule_manager.py       расписание, первичный сбор в фоне
  source_manager.py         сбор → запись в базу → история цен → уведомления → алерты
  source_health.py          состояние источника для алертов
  base_source_processor.py  общий HTTP: паузы между запросами, повторы, таймауты
  source_processor_1.py     разбор первого источника
  source_processor_2.py     разбор второго источника
  source_processor_3.py     разбор третьего источника (JSON API)
  parsing_utils.py          форматирование цен и чисел
  models.py                 модели SQLAlchemy
  config.py                 настройки из переменных окружения
  bot/
    bot.py, handlers.py     команды /start и /help
    notifications.py        отправка в группу и админу, фото, повторы
    templates.py            тексты сообщений, хэштеги
scripts/
  init_db.py                создание таблиц, недостающих колонок и источников — при каждом старте
data/
  sources.json.gpg          зашифрованный список источников (в git)
  sources.json              расшифрованный (в .gitignore)
```

## Настройка

### Переменные окружения

Задаются в `.env` в корне проекта. На сервере `.env` формирует деплой из секретов репозитория.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | токен бота от @BotFather |
| `CHANNEL_CHAT_ID` | да | — | id группы, формат `-100…` |
| `NEW_THREAD_ID` | нет | — | тема для новых машин, если у источника не задана своя |
| `PRICE_DROP_THREAD_ID` | нет | — | тема для снижений цен, если у источника не задана своя |
| `ADMIN_CHAT_ID` | нет | — | личный чат для алертов; без него алерты пишутся только в лог |
| `USER_PASSWORD` | нет | — | пароль для `/start <пароль>` |
| `NOTIFY_PRICE_DROP_PERCENT` | нет | `5` | порог снижения цены, % |
| `SILENT_CAR_TYPES` | нет | `passenger` | типы, о которых посты приходят без звука: `passenger`, `cargo`, `trailer` |
| `NEW_CARS_HOURS` | нет | `9-18` | часы поиска новых (МСК) |
| `NEW_CARS_INTERVAL_SECONDS` | нет | `0` | поле `second` cron: `0` — раз в минуту |
| `UPDATE_CARS_HOURS` | нет | `10,12,14,16,18` | часы обновления цен (МСК); полный обход всех источников ~20 минут |
| `WORK_DAYS` | нет | `mon-fri` | дни работы расписания |
| `DAILY_SUMMARY_HOUR` | нет | `19` | час (МСК) отправки итогов дня в общий чат |
| `IS_DEBUG` | нет | `false` | `true`: поиск новых каждые 5 секунд, круглосуточно и без выходных |

`DATABASE_URL` и `SOURCES_PATH` уже заданы в `docker-compose.yml`.

> Не оставляйте `NEW_THREAD_ID` и `PRICE_DROP_THREAD_ID` пустыми (`NEW_THREAD_ID=`) — приложение упадёт на старте. Либо число, либо строки нет вовсе. Без темы сообщения уходят в общий чат группы.

**Как узнать id темы:** в Telegram откройте тему → «Копировать ссылку» → `https://t.me/c/<группа>/<id темы>`.

**Бот должен быть в группе** администратором с правом отправлять сообщения, иначе Telegram ответит `Chat not found`.

### Источники

`data/sources.json` — список источников:

```json
[
  {
    "source_id": "<ключ>",
    "name": "<название для сообщений>",
    "base_url": "https://<сайт>",
    "template_url": "https://<сайт>/<каталог>/%s/?page=%s",
    "new_thread_id": 12,
    "price_drop_thread_id": 13
  }
]
```

`new_thread_id` и `price_drop_thread_id` — темы группы, куда уходят новые машины и снижения цен этого источника. Если их нет, используются общие `NEW_THREAD_ID` и `PRICE_DROP_THREAD_ID`.

Формат `template_url` зависит от процессора источника: у одного подставляются тип и страница, у другого только раздел каталога.

При старте `init_db.py` сверяет файл с таблицей `sources`: добавляет новые записи и обновляет изменённые. Порядок записей важен: процессор выбирается по `id` в базе (`get_source_processor` в `source_manager.py`).

В git хранится только зашифрованная версия. После правки файла перешифруйте его и закоммитьте `data/sources.json.gpg`:

```bash
SECRET_KEY='<пароль>' bash encrypt.sh
```

Расшифровать:

```bash
SECRET_KEY='<пароль>' bash decrypt.sh
```

## Локальный запуск

Нужны Docker, `.env` и расшифрованный `data/sources.json`.

```bash
docker compose up -d --build
```

```bash
docker compose logs -f app
```

> Первый запуск на пустой базе отправит в группу первые страницы каталогов как новые машины. Для экспериментов используйте тестовую группу.

## Деплой

Push в `main` запускает GitHub Actions ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)):

1. **build** — проверка синтаксиса, сборка образа, публикация в GHCR с тегами `latest` и `<sha>`.
2. **deploy**:
   - расшифровка `sources.json` на раннере;
   - формирование `.env` из секретов;
   - копирование на сервер `docker-compose.yml`, `.env` и `data/sources.json`;
   - `docker compose pull` и `up -d`;
   - проверка через 20 секунд, что контейнер работает и не перезапускается. Если нет — job падает с последними строками лога.

Ручной запуск: Actions → Deploy to Server → Run workflow.

### Секреты репозитория

| Секрет | Назначение |
|---|---|
| `SSH_HOST`, `SSH_PORT`, `SSH_USER` | доступ к серверу |
| `SSH_PRIVATE_KEY` | приватный ключ без пароля; публичный — в `~/.ssh/authorized_keys` на сервере |
| `GPG_SECRET_KEY` | пароль от `sources.json.gpg` |
| `TG_BOT_TOKEN` | → `TELEGRAM_BOT_TOKEN` |
| `TG_CHANNEL_ID` | → `CHANNEL_CHAT_ID` |
| `TG_BOT_ADMIN` | → `ADMIN_CHAT_ID` |
| `TG_NEW_THREAD_ID` | → `NEW_THREAD_ID` (необязательный) |
| `TG_PRICE_DROP_THREAD_ID` | → `PRICE_DROP_THREAD_ID` (необязательный) |
| `USER_PASSWORD` | → `USER_PASSWORD` (необязательный) |

Необязательные секреты, если они пустые, в `.env` не попадают. `NOTIFY_PRICE_DROP_PERCENT` и настройки расписания деплой не передаёт — на сервере действуют значения по умолчанию.

### Подготовка сервера (один раз)

```bash
sudo usermod -aG docker $USER
```

```bash
sudo mkdir -p /opt/car-bot/data /opt/car-bot/logs && sudo chown -R $USER:$USER /opt/car-bot
```

После `usermod` нужно перелогиниться. На сервере должен быть Docker с плагином `docker compose` (v2).

## База данных

Таблицы создаёт `scripts/init_db.py` при каждом старте контейнера. `create_all` не добавляет колонки в существующие таблицы, поэтому новые колонки дописываются там же идемпотентным `ALTER TABLE … ADD COLUMN IF NOT EXISTS` (см. `add_missing_columns`). Новая колонка в модели — это новая строка в этом методе.

`scripts/migrate.py` — устаревший скрипт под SQLite, нигде не вызывается. Не запускайте его на PostgreSQL.

Postgres слушает только `127.0.0.1:5432`.

## Добавление источника

1. Создайте `src/source_processor_N.py` — наследник `BaseSourceProcessor`:
   - реализуйте `scrape_new_cars` (первые страницы, от новых к старым) и `scrape_updated_cars` (полный обход);
   - запросы делайте через `self._get()` — пауза, повторы и учёт ошибок для алертов работают автоматически;
   - остановка обхода — по признаку последней страницы: многие сайты за последней страницей молча отдают первую;
   - `car_id` должен быть уникален на всю таблицу — добавьте префикс источника, как `s2:` во втором процессоре;
   - заполняйте `title`, `brand`, `price`, `monthly_payment`, `city`, `mileage`, `year`, `detail_url`, `image_url`.
2. Подключите процессор в `get_source_processor` (`src/source_manager.py`).
3. Добавьте источник в `data/sources.json` и перешифруйте файл.
4. Учтите, что первый запуск отправит первые страницы нового источника в тему «новые».

## Эксплуатация

Логи:

```bash
docker compose logs --tail=200 app
```

Только ошибки и отправки:

```bash
docker compose logs app | grep -E "❌|ERROR|Отправка|Фото не принято|Снижений меньше"
```

Состояние базы:

```bash
docker compose exec -T postgres psql -U car_user -d car_bot -c "select source_id, count(*), count(brand) from cars group by 1;"
```

| В логе | Что значит |
|---|---|
| `skipped: maximum number of running instances reached` | поиск новых ждёт окончания полного обхода — норма |
| `Снижений меньше 5%: N — без уведомления` | снижения ниже порога, цены в базе обновлены |
| `Фото не принято (…), отправляем текстом` | уведомление ушло без фото |
| `Попытка 1 из 3 не удалась` | сетевой сбой, запрос повторяется |
| `Не отправлено N из M сообщений` | часть уведомлений не дошла после всех повторов |

Машины, снятые с продажи, остаются в базе: обход до них больше не доходит, поэтому марка и цены у них не обновляются.
